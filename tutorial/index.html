A puzzle in whole numbers

Square-Sum Pairs

Take the numbers 1 to n and split them into pairs, so that every pair adds up to a perfect square. When can you do it? How many ways are there? And how would a computer find them all?

Part 1 — The puzzle

Pair them up

Here are the numbers 1, 2, 3, 4, 5, 6, 7, 8. Your job: match them into four pairs so that each pair’s sum is a perfect square — a number like 4, 9, 16, 25 that equals some whole number times itself.

Click a number, then click its partner. If the sum is a perfect square the link turns green; if not, it turns red and springs apart. Pair all eight and you’ve solved it.

Pick any two numbers to start.

There’s exactly one way to do it: 1+8, 2+7, 3+6, 4+5 — every pair makes 9.

Try the same puzzle with 1 to 10, or 1 to 12, and you’ll get stuck every time. It isn’t that you’re missing a trick — there is no solution for those. Part of the fun of this kind of maths is that “impossible” is a real, provable answer.

The numbers 1 to 18 can be paired, and there’s only one way. Past a certain point the number of solutions explodes. To see why, it helps to redraw the puzzle.

Part 2 — Turn it into a picture

A map of who can pair with whom

Draw a dot for each number. Whenever two numbers add up to a perfect square, join their dots with a line. Mathematicians call this picture a graph — the dots are nodes, the lines are edges. (Nothing to do with the x-y graphs from algebra class.)

Now the puzzle has a clean description. A solution is a choice of edges that covers every dot exactly once — every number gets one partner, nobody is left over, nobody is used twice. A set of edges like that is called a perfect matching.

Look at the graph for n = 18. Some numbers are fussy: 16 touches only 9, 17 touches only 8, 18 touches only 7. Those numbers have no choice — a fact we’ll lean on hard in Part 4.

Part 3 — Why you can’t just try everything

The pile of possibilities

The lazy plan: list every possible way to pair up the numbers, then keep the ones where all the sums are square. How big is that list?

With 2k numbers, the count of ways to split them into pairs is 1 × 3 × 5 × 7 × ⋯ × (2k−1) — multiply every odd number up to 2k−1. It grows fast.

So brute force is out. We need a search that throws away huge batches of hopeless pairings without ever looking at them one by one.

Part 4 — The smart search

Backtracking: guess, and be ready to un-guess

Here’s the idea. Keep a running list of pairs you’ve committed to. Then repeat:

  • Pick a number that isn’t paired yet.
  • Try giving it a partner. Add that pair to the list and move on.
  • If you ever reach a number with no legal partner left, you’ve hit a dead end. Undo the last guess and try the next option.
  • If every number is paired, you’ve found a solution. Record it and keep exploring for more.

That “undo the last guess” step is backtracking. It’s recursion with an eraser. Watch it run on n = 26 — which has six solutions — one step at a time.

Shortcut 1 — forced moves

Remember the fussy numbers? If a number has exactly one partner available, there’s nothing to decide — pair them immediately, before guessing anything. Doing this repeatedly often triggers a chain reaction: one forced pair makes another number fussy, which forces the next.

For n = 18 the chain reaction does the entire job. The search never makes a single free choice:

all forced · n = 180 guesses

The same trick on n = 10 marches straight into a wall — 2 and 3 are left needing each other, but 2+3=5 isn’t square. That’s a clean proof that n = 10 has no solution at all.

Shortcut 2 — deal with the fussiest number first

When the search does have to guess, which number should it guess about? The one with the fewest options. If a number has only two possible partners, trying both is cheap and you learn a lot. If you instead guess about a number with six options, you build a wide, shallow tree of possibilities that mostly leads nowhere.

Part 5 — How many solutions?

A desert, then an avalanche

Run the search for every even n and count. The pattern is strange and lovely: nothing at all for a while, a lone solution here and there, then — once n reaches 24 — it never stops climbing.

The counts in full. This sequence is catalogued as OEIS A252897.

Nobody has a formula for these numbers. Each one is found by search. The count is known up to about n = 84; past that, the trees are too big for today’s computers to finish. That’s a genuine unsolved corner of mathematics you just walked up to.

Go further

  • Change the rule. Pairs that sum to a prime? To a cube? To a Fibonacci number? Each gives a different graph and a different puzzle.
  • Ask for a loop instead of pairs. Arrange 1…n in a circle so every neighbouring sum is square. That’s the famous “square-sum problem” — a matching becomes a Hamiltonian cycle.
  • Prove the desert. Can you show from the graph alone why n = 12 has no perfect matching? (Hint: find a small group of numbers that between them don’t have enough partners.)
  • Estimate the avalanche. The counts seem to grow geometrically. Fit a curve to the table and predict n = 62. Then check against a real search.
